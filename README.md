# Anmore Social

A quiet, photo-friendly community bulletin. The community feed comes first; upcoming events are secondary. Readers need no account. Static files are served by GitHub Pages at `anmore.social`.

## The trust contract

- **Automatic eligibility, no human approval:** a valid signed profile and exact current HTTPS domain mapping admit any eligible handle; there is no moderation approval, name/key allowlist, sentiment classifier or editorial queue. Newest is default. Optional **Top zapped** ranks only loaded posts by verified community Lightning receipts, not positivity or personalized engagement.
- **Content relay only:** posts, profiles, calendar entries and signed removals come exclusively from `wss://relay.anmore.me`. The only exception is receipt-only kind 9735 cross-reference on fixed `wss://relay.primal.net` for approved issuer/recipient and already accepted loaded post IDs. No content/profile fallback, federation or metadata-derived relay destinations.
- **Dynamic author eligibility:** any exact `handle@trailscoffee.com` with a case-preserving ASCII handle of 1–64 characters matching `[A-Za-z0-9_.-]{1,64}` is eligible. A cryptographically verified signed kind-0 profile must claim it; HTTPS `https://trailscoffee.com/.well-known/nostr.json?name=EXACT_HANDLE` must map that exact own name to the same lowercase hex public key. Redirects are rejected, credentials omitted, responses byte-bounded to 64 KiB (65,536 bytes). Case normalization, suffix/lookalike domains, malformed responses, key mismatch and transport failure never grant new admission. NIP-05 is a domain association, not proof of post accuracy.
- Every event is shape/hash/Schnorr verified over canonical NIP-01 fields; relay extras/cache flags are never authority or retained as signed payload. Malformed events, invalid signatures and timestamps later than the current reader clock are rejected with no future-clock tolerance. Community-recipient discovery separately uses the canonical whole directory, a 128-name ceiling and current signed profiles.
- Main feed: kinds 1 and 20, newest **signed `created_at`** first by default, lexical event-ID tie-break and ID deduplication. Optional Top zapped sorts verified millisatoshi totals, then newest/ID; it is visibly **among loaded posts**, never global Top. Newest starts with 12 entries. Top and subsequent latest catch-up read at most six content pages/600 raw entries per action. Head refresh merges without clearing loaded older rows or moving their independent completed cursor. No personalization, likes, replies, follows, account/key storage, publishing controls or infinite scroll.
- **Top timeframe controls:** All time is initially selected in Top; This week begins Monday 00:00 and This month the 1st 00:00 in America/Vancouver. Ranking and displayed amounts use signed receipt time, not post age. Starts are inclusive, ends exclusive; future receipts are rejected. Global payment deduplication/conflicts run before period filtering, with earliest duplicate time. Switching periods never requests invoices or adds relays. Newest hides the controls and uses all-time card amounts.
- **Durable acceptance, not source-presence eviction:** canonical signed posts/calendar bodies, event-bound signed kind-0 profile plus exact historical HTTPS name mapping and verification time, signed tombstones, restrictive revision/profile highwaters, identity revocations, verified raw receipt claims/provenance and completed checkpoints are retained transactionally in IndexedDB (`anmore-accepted-v1`). Relay absence, missing exact-ID responses, empty EOSE, transient identity expiry/outage, offline refresh and receipt failure do **not** erase accepted history. There is no accepted-history age/count pruning or former 1,200-post session ceiling. Signed author deletions and real authoritative identity contradictions/withdrawals can revoke projection. Subsequent fresh valid mapping can restore eligibility without approval.
- Calendar: latest addressable revisions of kinds 31922/31923, ordered by upcoming start in Pacific time. Four upcoming loaded entries are shown, never an exhaustive-calendar claim. All-day dates remain calendar dates, not UTC-midnight conversions. Calendar admission uses the same author trust gate.
- **Deletion:** signature-valid same-author NIP-09 `e` references remove exact targets without an invented timestamp restriction; `a` references remove matching addressable revisions inclusively through the deletion timestamp. Foreign/forged requests have no authority. Tombstones work before/after target delivery and across restart; deleted newer revisions retain their restrictive highwaters, so older bodies cannot replay. Profile deletion retires current author permission, not unrelated historically accepted posts. Known retained/new targets are reconciled with independent exact `#e`/`#a` canonical-relay reads; receipt removals require the historical issuer signer, never a replacement provider key. Absence is not a signed deletion.

## Per-post community Lightning zaps

All sats go to the community group, **not the author**, at the exact owner-supplied address `coffeeloverc2c2cd@pay.trailscoffee.com`. There is **no generic donation QR/address handoff**. The address and technical post details are informational inside a collapsed disclosure in the post-specific dialog. An explicit amount/request action rechecks the current signed post, author NIP-05/deletions, community recipient profile/directory, and the fixed HTTPS pay endpoint. It signs one NIP-57 request with a fresh anonymous in-memory key, clears that key buffer, serializes once, and requests an invoice from the exact approved callback. No user identity, key persistence, wallet access, payment sending, or Cashu operations are used.

Only a signature-verified, mainnet whole-satoshi BOLT11 with exact request hash, amount, and fresh nonexpired timing is exposed as a local QR/Lightning wallet handoff. Invoice creation is not payment. One callback attempt per post per page session (maximum 32), no automatic retry; reopening reuses the same invoice while valid. Refresh invalidates the dialog. Expired or ambiguous attempts are not silently replaced; users are told to check their wallet. The client has no payment-status/custody authority. The compact dialog asks for sats with **Get invoice**, then hides the amount form and prioritizes **Copy invoice** (the exact raw BOLT11). **Open wallet** is only a generic `lightning:` handoff, not a verified Trails-specific launcher. The copy confirmation suggests pasting in Trails Wallet; no unique Trails wallet scheme or iOS URL handler is claimed. QR is behind **Show QR**, raw text appears only in a manual-copy fallback after clipboard denial, and neither payment nor wallet navigation starts automatically.

Totals count only verified kind-9735 receipts from the endpoint's approved **receipt issuer**, with a separately resolved community **recipient**, signed embedded request, exact post/recipient, invoice description hash over the original description bytes and invoice amount. NIP-57 makes request `lnurl` optional; if supplied it must exactly match the community endpoint, with duplicate/mismatched tags rejected. Notification relay lists are not authority and are never followed. Claimed receipt amount tags are not used. Payment hashes deduplicate across event IDs; conflicting reuse contributes zero. Sender NIP-05 is not required. Counts are provider-attested receipts, not independent cryptographic proof of Lightning settlement. A bounded snapshot can omit/withhold receipts; zero verified sats does not prove no payments. Both fixed relay reads run concurrently with independent four-second receipt deadlines. One healthy source survives the other failing: positive amounts show **N sats · provisional**, missing totals show **—**, with an explicit partial receipt-check note that totals/order may change as receipts become available. These observed snapshots can decrease as well as increase: an earlier verified duplicate can move a payment outside the selected period, and a conflicting payment binding excludes it entirely. If both sources fail, retained authenticated amounts remain explicitly provisional; without retained claims checks are unavailable, never invented verified zero. Each source receives one kind-9735 filter containing at most 1,200 exact visible post IDs, limit 1,000; a source reaching that ceiling is discarded as truncated. Event-ID merging retains durable raw authenticated claims and source provenance, then global payment-hash deduplication/conflict detection runs before week/month/all-time filtering, including after restart and signed receipt removal. Old claims are not discarded when a later snapshot omits them. Provider rotation never grants the replacement key authority over an old claim. Content renders before receipt reads finish. NIP-61 nutzaps are explicitly unavailable, not mixed into Lightning totals.

**Read-only paid-receipt reconciliation passed; release remains gated on independent review:** see `RECEIPT_READINESS.md` for three actual verified receipts (50, 42 and 21 sats), live browser pagination and exact source boundary. Historical unpaid invoice/QR evidence: see `ZAP_READINESS.md`. Two earlier noncanonical requests failed exact hash binding and remain recorded as failures. The frontend now constructs the producer's Nostr field order before sending (never normalizes an invoice hash). One subsequent bounded unpaid 21-sat request passed exact raw-request SHA-256, amount, signature and timing checks; its actual dialog QR independently decoded at 320/390/768/1440 CSS pixels. No payment or receipt publication was attempted. Unpaid invoice/QR evidence is private local evidence, not proof of settlement or receipt delivery.

## Safe rendering

Untrusted text is built with DOM text nodes, never HTML interpolation. HTTPS links are explicit new-tab links with `noopener noreferrer`. Credentials, local/IP hosts, non-HTTPS URLs and executable schemes are not admitted. Up to four HTTPS images per post are lazy-loaded with no referrer; unavailable images become original-image links. Photos are not cropped. External media hosts still receive the reader's IP; source navigation leaves the site. No analytics or browser identity storage is used. Public sources and original source links remain in the text; each card also exposes its relay, author key, event ID, signature and timestamp.

Relay disconnection, declined requests, timeouts, oversized responses and identity-endpoint failures are visible. Previously accepted content remains explicitly last-checked/stale, including offline cold launch. New admission still requires a current signed profile and fresh exact HTTPS proof; historical receipts never become reusable author or invoice authority. No demo posts are shipped, and this application never publishes content.

The old identity manager, native composer, calendar grid, World Cup data, and fallback relays remain removed.

## Optional installation and offline boundary

The owner explicitly authorized installation, then durable browser history and offline app-shell caching. This **supersedes the former no-content-cache and source-absence-eviction policies**, not cryptographic admission, fixed recipient, invoice rechecks or explicit update/session safeguards. `sw.js` retains its root URL and `updateViaCache: "none"` for migration from legacy/retirement workers. Earlier readiness reports describe their historical release scopes, not the new storage policy.

The owner's later UX correction supersedes the original footer/engagement placement: a compact, dismissible install banner now appears **at the top on the initial browser visit**, with finite entrance/icon motion that is disabled for reduced motion. Top install help remains reachable after dismissal and without JavaScript; platform-specific instructions and the single-use native button are available there. The banner is in normal flow, not sticky or an overlay, and never automatically invokes the browser prompt. Redundant mobile welcome artwork/copy is compacted to preserve the unchanged first-post geometry gate. There is no duplicate footer install CTA.

Dismissing the banner or receiving a native install result sets a seven-day local cooldown; denied storage falls back to memory. The sole optional preference is `anmore-install-dismissed-at`, a timestamp with no identity, content, engagement history, analytics or network transmission. It is written only after dismissal or an install outcome, never merely for visiting/reading. Standalone mode and `appinstalled` suppress installation surfaces. Installation remains optional and browser-dependent. Existing manifest identity, scope, start URL, icon bytes and icon URLs are unchanged: the owner confirms the installed home-screen logo is correct. Explicit Open Graph/Twitter metadata selects that existing branded icon for link previews; the reported firefighters preview's exact cause remains unproven. See `TOP_INSTALL_READINESS.md` for this scoped correction and local evidence.

The worker preinstalls the exact reviewed same-origin shell in `anmore-social-shell-v1`: `index.html`, `app.js`, `feed.css`, `manifest.webmanifest`, `icons/icon-192.png`, `icons/apple-touch-icon.png`, `offline.html`, `offline.css`. It serves this version coherently cache-first, including root/index navigation with no query or exact `?source=pwa`, and exact versioned script/CSS queries. **There are no runtime cache writes.** Invoices, payment/identity endpoints, receipts, wallet paths, arbitrary queries and external media bypass the worker and are never HTTP-cached by it. Public accepted evidence is separately in IndexedDB. Offline cards/totals are display-only; cached evidence cannot enable invoice creation. Browser-managed HTTP caching is separate. Bump the shell cache version and reviewed asset query version together whenever reviewed shell bytes change.

Updates wait by default: no install-time `skipWaiting`, forced reload or automatic invoice-session reset. Explicit finished-with-tips/saved-invoice acknowledgement is required before **Update and reload**; an open zap dialog blocks activation. Only the consenting tab arms reload; other tabs retain invoice sessions. Automatic feed polling also pauses while a zap dialog is open. Activation removes only obsolete owned `anmore-social-pwa-*`, `anmore-social-offline-*`, `anmore-social-shell-*` caches, never unrelated caches or IndexedDB history. Legacy controlled clients need an online visit and explicit update (or all controlled tabs closed) before the new policy applies.

The app icons now use the site’s mountain mark rather than the legacy Trails Coffee wordmark. `icons/anmore.svg` is the self-contained source; `npm run icons:pwa` regenerates the PNG variants with local Chromium. Dedicated opaque maskable artwork is pixel-tested inside the central 80%-diameter safe circle. Orientation is not locked; manifest theme matches the page.

## Local development and verification

Node 24 was used. No framework or runtime CDN dependency is required: `app.js` bundles the pinned verifier/signing primitives, invoice reader and QR encoder. New local work must rebuild the bundle before review.

```sh
npm ci
npm test
npm run build
python3 -m http.server 4173 --bind 127.0.0.1
# In another terminal:
npm run qa
QA_URL=http://127.0.0.1:4173 node tests/receipt-live-qa.js
```

Browser QA uses Playwright with `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`; set `CHROME_PATH` for another installed Chromium path. Set `QA_URL` to a separate local port when 4173 belongs to another worktree. Fixture QA is explicitly synthetic and includes an intercepted relay, invented identities and a generated landscape image. It tests 1440/768/390/320 CSS-pixel layouts, chronological pagination, malicious content, provenance, dynamic identity, durable public evidence (but no reader identity, private-key or invoice storage), deletion across pagination/reload, failed identity resolution, key mismatch, relay refusal, empty and offline states. Axe checks WCAG A/AA rules. The Top-button suite additionally exercises an older 1,250-sat winner without manual pagination, a fifth-page winner, six-page bounds, deletion of the highest amount, failure recovery, pressed state, keyboard selection and side-by-side 44px controls. Dialog fixtures verify exact raw-invoice copying, optional QR pixel decoding, clipboard fallback, and all primary actions visible at 320/390 × 480. Live QA makes real read-only Anmore content and Primal receipt requests plus actual HTTPS NIP-05/recipient endpoint reads, captures separate `qa/live-*` evidence, and never publishes. Screenshots and JSON evidence stay in ignored `qa/`, not production content.

Bounds apply to network intake and quarantine, **not accepted history**: 12 initial feed entries; six content reads/600 raw page entries per Top/latest catch-up; inclusive timestamp ties with a 600-boundary ceiling; 60 latest calendar entries and 64 rotating retained-address checks; 32 rotating known-author renewals plus candidate authors; exact removal batches of 64 with a 500-response fail-closed ceiling; rotating receipt windows of up to 1,200 loaded posts, independently capped 1,000-frame receipt sources; pending candidates at most 500/2 MiB; unknown profiles at most 512/2 MiB, unknown identity status records 512; unknown tombstones at most 128/256 KiB and 16 KiB per removal. Relevant accepted evidence is never evicted to meet quarantine budgets. Saturation/failure is incomplete coverage, not proof of global history or deletion. A relay can withhold history.

## Browser sync, recovery and local trust

Only a runnable **visible tab** synchronizes directly with `wss://relay.anmore.me`, approximately every 60 seconds, with single flight, focus/visibility/online resume, a 15-second automatic throttle and capped exponential failure backoff. Manual refresh retries explicitly. No closed-tab polling, server service, new backend, cache relay or relay changes are introduced. Signature creation times are not relay insertion cursors: inclusive `since` overlaps by 300 seconds; every fifth latest pass performs bounded newest reconciliation without `since` to find backdated arrivals within that window. This cannot guarantee discovery of arbitrary late/backdated history outside the bounded window. Older pagination remains explicit and independent. A nonempty initial head seeds its checkpoint from the oldest timestamp of its first completed page, not wall-clock time or a claim that history is complete. The next head read uses the inclusive overlap without scanning all older history; only a completed `since` window advances to wall-clock time. Failed/truncated latest reads never advance an established latest checkpoint; interrupted older requests cannot advance their completed boundary. Saturated timestamp ties retain the checkpoint and incomplete status rather than skipping unseen tied rows; repeated bounded reads may stall until the window can be drained. Identity-outage candidates retry from bounded in-memory quarantine without bypassing fresh proof; unaccepted candidates are not durable across restart and may require reconciliation or explicit older reads. Period projections rerender on the visible timer and on period selection.

Cold launch restores and cryptographically rechecks accepted signed payloads and event/profile/mapping bindings before projection, without waiting for relay/HTTPS refresh. Historical HTTPS mapping/provider response evidence is **not a portable signed proof**: integrity of same-origin application code and browser storage is assumed. Fresh author proof is required for every new acceptance (maximum 300-second admission age); restored proof is historical only. New invoices still use unchanged exact post/profile/deletion/current HTTPS recipient/endpoint rechecks and the 60-second invoice-authority gate. No secret keys, invoices, attempts or wallet/payment sessions are persisted.

Read/decode/schema/unsupported-store failures latch a write block and preserve the old generation. Refresh retries the exact generation, merging accepted memory and restrictive tombstones/highwaters/revocations before any replacement; offline retry can recover readable saved history too. Concurrent owners merge in a single IndexedDB read/write transaction. Failed writes/aborts/quota errors keep the prior complete generation and current memory, with an explicit memory-only save warning; an unsaved update is **not** promised to survive restart. Browser storage can be user-cleared, evicted or denied, so this is durable best-effort local history, not an archive/backup guarantee. Clearing site data removes local history.

`tests/durable-browser.test.js` uses real Chromium IndexedDB, canonical signed fixtures and intercepted relay/HTTPS boundaries. It exercises cold/offline shell reload, failed refresh, recovery from corrupt/unsupported generations and actual transaction aborts, head/older separation, tie/backdated recovery, restart tombstones/highwaters, current-proof expiry, dynamic eligibility, durable receipt replay/conflicts/removals/provenance, cross-tab merge and unpruned old history. No live invoice callbacks or payments are used. CDP quota override did not actually enforce IndexedDB quota in this local Chrome; real quota-exhaustion/physical-device eviction remain separate manual gates, not fabricated test evidence.
